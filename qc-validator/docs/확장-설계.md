# 향후 GC-MS/MS 및 미생물 분석 확장 설계

BIOPILOT · 분석 엔진 v1.0.0 · 생성일 2026-11-11 · `node scripts/gen-docs.mjs`가 만든 문서다.

> 이 문서는 설계안이다. 여기 적힌 기능은 구현되어 있지 않다. 기준 수치는 구현 시점에 해당 분석법 원문에서 확인해 예시 기준으로 넣는다.

## 1. 현재 구조에서 재사용되는 것

```
파일 → parse.js (형식·매핑·검증) → 레코드
레코드 → analyze.js → [calibration.js → qc.js] → 판정(findings)
판정 → diagnose.js (규칙 기반 가설) → llm.js (선택) → report.js
```

- `stats.js`의 통계 함수, `parse.js`의 파일 판독과 "값을 채우지 않는" 검증, `rules.js`의 설정 가능한 규칙 구조, 판정 객체의 형태(코드·관측값·기준·근거), 진단 카드의 형태(관측 사실·가설·확인·검증·원인 미확정), 보고서와 검토 기록은 분석 종류와 무관하다.
- 분석 종류마다 달라지는 것은 (1) 입력 필드, (2) 정량 모형, (3) QC 항목과 기준, (4) 진단 지식이다.

## 2. 분석 종류 모듈(assay module) 인터페이스

`src/assays/<이름>/`에 다음 네 가지를 둔다. 현재의 LC-MS/MS 코드를 첫 모듈로 옮기는 것이 1단계다.

| 구성 | 역할 | LC-MS/MS에서의 현재 위치 |
|---|---|---|
| fields | 입력 필드 정의와 머리글 동의어, 시료 유형 | parse.js의 FIELDS, TYPE_SYN |
| quantify | 검량·정량 모형과 적합성 판정 | calibration.js |
| checks | QC 항목 계산과 판정 | qc.js |
| rules | 규칙 메타데이터, 예시 기준 묶음 | rules.js |
| knowledge | 오류 코드별 진단 카드 생성기 | diagnose.js의 BUILDERS |

`analyze(records, settings, meta)`는 레코드의 분석 종류에 맞는 모듈을 불러 같은 형태의 결과를 돌려준다. 화면은 모듈이 내놓는 표와 그래프 정의를 그린다.

## 3. GC-MS/MS 확장

### 추가 입력 필드

| 필드 | 용도 |
|---|---|
| Qualifier Ion Area / Ion Ratio | 확인 이온과 정량 이온의 비로 피크 동정 확인 |
| Surrogate Name / Surrogate Area | 시료마다 넣는 대체표준물질의 회수율 |
| Tune Check 결과 | 질량 축·분해능 점검(예: DFTPP, BFB 기준 충족 여부) |
| Response Factor 관련(내부표준 농도) | 상대감응계수(RRF) 방식 검량 |
| Injection Port / Liner 교체 시점 | 주입구 열화 진단의 문맥 |

### 정량 모형

- 평균 상대감응계수(RRF) 방식을 추가한다: 수준별 RRF의 RSD로 직선성을 판정하고, RSD가 기준을 넘으면 회귀 방식으로 전환하도록 안내한다.
- 현재의 가중 선형 회귀는 그대로 쓴다.

### 추가 QC 항목(오류 코드 초안)

| 코드 | 내용 | 필요 데이터 |
|---|---|---|
| ION_RATIO | 이온비가 검량 표준 평균에서 허용 범위를 벗어남 | 확인 이온 면적 |
| SURR_RECOVERY | 대체표준물질 회수율 이상 | 대체표준 면적·농도 |
| CCV_DRIFT | 연속 검량 검증 표준의 응답이 초기 검량에서 벗어남 | CCV로 표시된 주입 |
| RRF_RSD | 수준별 감응계수의 RSD 초과 | 내부표준 농도 |
| TUNE_FAIL | 튠 점검 미통과 | 튠 결과 |
| BREAKDOWN | 열분해 지표 화합물의 분해율 초과(주입구 활성) | 분해 점검 주입 |

### 진단 지식의 차이

- 머무름 시간 이동: 컬럼 절단·교체, 운반기체 유량·누설이 주요 후보가 된다.
- 응답 저하: 주입구 라이너 오염, 격막 누설, 이온원 오염을 후보에 넣고, 고비점 화합물만 낮아지는지(주입구 차별)로 구별 근거를 만든다.
- 매질 효과: GC에서는 매질에 의한 응답 증강이 흔하므로 회수율이 높은 경우의 가설 순서를 바꾼다.

## 4. 미생물 분석 확장

정량 모형이 검량선이 아니라 계수(count)이므로 `quantify`와 `checks`를 새로 만든다.

### 입력 필드

| 필드 | 용도 |
|---|---|
| Dilution(10⁻ⁿ), Plated Volume | 집락 수를 CFU/mL(또는 /g)로 환산 |
| Colony Count, Plate Replicate | 평판별 집락 수 |
| Medium / Lot, Incubation Temp·Time | 배지와 배양 조건 기록 |
| Control Type(양성·음성·무균·배지 성능) | 대조군 판정 |
| MPN Tube Pattern | 최확수법의 양성 시험관 조합 |
| Presence/Absence 결과 | 정성 시험 |

### 계산

- 계수 가능 범위 안의 평판만 써서 가중 평균으로 CFU를 계산한다(범위와 가중 방식은 적용 표준에서 확인해 규칙으로 둔다).
- 범위 밖 평판만 있을 때는 "추정값"으로 표시하고 정량값처럼 다루지 않는다.
- 최확수는 표준 표 또는 최대우도 계산으로 구하고 신뢰구간을 함께 낸다.
- 결과는 로그 변환 값으로 정밀도를 평가한다.

### QC 항목(오류 코드 초안)

| 코드 | 내용 |
|---|---|
| NEG_CONTROL_GROWTH | 음성·무균 대조에서 집락 검출 |
| POS_CONTROL_FAIL | 양성 대조 또는 배지 성능 시험 미충족 |
| DUP_PLATE_DISPERSION | 중복 평판의 차이가 포아송 분포로 설명되는 범위를 넘음 |
| DILUTION_INCONSISTENT | 연속 희석 단계 사이의 집락 수 비가 희석배수와 맞지 않음 |
| COUNT_OUT_OF_RANGE | 계수 가능 범위 밖의 평판만 있음 |
| INCUBATION_DEVIATION | 배양 온도·시간이 허용 범위를 벗어남 |
| HOLD_TIME | 시료 채취에서 분석까지의 시간 초과 |

### 진단 지식의 예

- 희석 단계 불일치: 희석 조작 오류, 혼합 부족, 집락 뭉침, 억제 물질의 희석 효과를 후보로 두고, 낮은 희석에서만 억제되는지로 구별 근거를 만든다.
- 음성 대조 오염: 배지·희석액 오염, 작업 환경, 교차 오염을 후보로 두고, 같은 배지 lot의 다른 대조 결과로 근거를 만든다.

## 5. 단계별 계획

1. **모듈 분리**: 현재 코드를 `assays/lcmsms/`로 옮기고 인터페이스를 고정한다. 기존 시험 112개가 그대로 통과해야 한다.
2. **GC-MS/MS**: 필드와 규칙 추가, RRF 정량, 이온비·대체표준·CCV 판정. 합성 시나리오와 정답표를 같은 방식으로 만든다.
3. **미생물**: 계수 모형과 대조군 판정. 포아송 분산 검정을 `stats.js`에 추가한다.
4. **공통**: 배치 간 추세(관리도), 장비·분석법별 규칙 묶음 저장, 감사 추적이 필요한 환경을 위한 서명·잠금.

## 6. 구현 전에 확인할 것

- 각 분석법의 기준 수치는 원문에서 확인한 뒤 "예시 기준"으로 넣는다. 이 문서에는 일부러 수치를 적지 않았다.
- 실제 사용자의 내보내기 파일 형식(넓은 형식, 분석물별 시트)을 받아 매핑 기능을 넓힌다. 지금은 긴 형식만 지원한다.
- 전자 기록 규제(감사 추적, 접근 통제)가 적용되는 환경에서는 브라우저 단독 도구로는 부족하다. 서버 저장과 사용자 인증이 필요하다.
